# Веб-інтерфейс Jules — реєстр тест-кейсів

Односторінковий застосунок (React 19 + react-router-dom 7 + Vite). Сторонніх
UI-бібліотек немає: стилі, компоненти станів, діалоги, тости й клавіатурні
скорочення написані тут. Мова інтерфейсу — українська, усі рядки в
`src/strings.ts`.

## Запуск

```bash
# бекенд (Express, порт 3840) — він же роздає зібраний web/dist
npm run ui:start

# окремо dev-сервер інтерфейсу (порт 5173, /api проксюється на 3840)
npm --prefix web run dev

# збірка і перевірка типів
npm --prefix web run build
npx tsc --noEmit -p web/tsconfig.json
```

## Розділи

| Адреса | Екран | Головне джерело даних |
|---|---|---|
| `/` | Дашборд: черга рішень, KPI, модулі, нестабільні кейси, останні прогони | `GET /api/registry/dashboard` |
| `/cases` | Реєстр: дерево секцій, таблиця, деталі кейса, масові дії | `GET /api/registry/cases`, `/sections`, `/cases/:id` |
| `/proposals` | Черга апрувів AI | `GET /api/registry/proposals` |
| `/runs`, `/runs/:id` | Прогони і режим проходження чек-листа | `GET /api/registry/runs`, `/runs/:id` |
| `/coverage` | Джерела вимог, матриця покриття, AI-скіли | `GET /api/registry/coverage`, `/sources` |
| `/settings` | Проєкт, інтеграції, мапінг TestRail, дефолти, журнал скілів | `GET /api/registry/testrail/mappings`, `/skills/runs`, `/api/settings` |

Фільтри, сортування, сторінка й вибраний кейс зберігаються в query-параметрах,
тому будь-який вид можна переслати посиланням.

## Режим фікстур (`?mock=1`) — інструмент розробки

Бекенд `/api/registry/**` може бути ще не готовий. Щоб перевіряти інтерфейс без
нього, є режим фікстур: клієнт API підміняється набором даних у пам'яті вкладки
(`src/api/mock.ts`).

**Це не «демо-режим» у продакшені.** Він не вмикається сам: потрібен явний
прапорець.

```
# увімкнути
http://localhost:3840/?mock=1

# вимкнути
http://localhost:3840/?mock=0

# або вручну в консолі браузера
localStorage.julesMock = '1'    // увімкнути
delete localStorage.julesMock   // вимкнути
```

Прапорець зчитується один раз під час завантаження модуля й запам'ятовується в
`localStorage`, тож далі можна ходити по розділах без параметра в адресі. Коли
режим активний, у нижньому лівому куті висить помітка «Режим фікстур (без
бекенду)».

Що є у фікстурах: один проєкт, 5 секцій, 12 кейсів, 7 блоків вимог із
прогалинами, 5 пропозицій (цитати й домисли), 3 прогони, дефекти, профіль
мапінгу TestRail і журнал скілів. Правки справді змінюють стан у пам'яті:
масова заміна з `dryRun` і відкотом, апрув пропозиції створює кейс, статуси в
прогоні перераховують зведення. Після перезавантаження сторінки все
повертається до початкового набору.

Режимом фікстур користується і `e2e/dashboard.spec.ts` — щоб смоук інтерфейсу
не залежав ні від наповненого реєстру, ні від LLM:

```bash
npm run test:ui
```

## Структура

```
src/
  api/
    client.ts        типізований клієнт: request(), AbortController, помилки, токен
    mock.ts          фікстури режиму розробки
    index.ts         вибір клієнта (справжній / фікстури)
  components/        каркас, стани, діалоги, тости, чипи, поля, логи рушія (SSE)
  context/           проєкт, тема, тости, ім'я користувача
  hooks/             useAsync / usePolling / useResource, query-параметри, клавіатура
  pages/             шість розділів + 404
  styles/
    tokens.css       ЄДИНИЙ файл токенів: палітра (світла й темна), відступи,
                     шкала тексту, радіуси, тіні, z-index
    app.css          базові стилі та компоненти
  strings.ts         усі рядки інтерфейсу
  types.ts           дзеркало src/registry/types.ts
```

### Правила, яких варто триматися

- **Типи.** `src/types.ts` — ручне дзеркало `src/registry/types.ts`. Змінюється
  контракт — правити обидва файли в одній зміні.
- **Рядки.** Жодного тексту для користувача в компонентах: тільки `S.…` зі
  `strings.ts`.
- **Кольори.** Жодних hex у компонентах: тільки `var(--…)` з `tokens.css`.
- **Запити.** Усе через `api` з `src/api`; кожен запит приймає `AbortSignal`.
- **Опитування.** Один хук `usePolling(fn, ms, { enabled })`; він сам зупиняється
  на неактивній вкладці (`document.hidden`) і скасовує запити при розмонтуванні.
  Ніяких `setInterval` по компонентах.
- **SSE vs опитування.** Логи прогону рушія — ЛИШЕ через SSE
  (`/api/runs/:legacyId/stream`, компонент `components/EngineLogs.tsx` із власним
  перепідключенням). Списки — ЛИШЕ через опитування. Одні й ті самі дані не
  тягнуться двома способами.
- **Стани.** Перше завантаження — `<Loading/>` (скелетон), помилка —
  `<ErrorState onRetry/>`, порожньо — `<Empty/>` з підказкою. «Немає даних» під
  час завантаження не показуємо ніколи.

## Тема

Світла палітра — на `:root`. Темна вмикається двічі: системно
(`@media (prefers-color-scheme: dark)` з guard `:root:not([data-theme="light"])`)
і вручну (`:root[data-theme="dark"]`). Перемикач у шапці пише вибір у
`localStorage.julesTheme`; читання й запис загорнуті в `try/catch`, бо сховище
може бути заблоковане. Щоб не блимало світлим до першого рендеру, тема
застосовується маленьким інлайн-скриптом в `index.html`.

## Клавіатура

| Клавіша | Дія |
|---|---|
| `/` | фокус у пошук |
| `j` / `k` | наступний / попередній рядок |
| `Space` | вибрати рядок |
| `Enter` | відкрити деталі / наступний кейс у прогоні |
| `1` `2` `3` `4` | у прогоні: пройдено / впало / заблоковано / пропущено |
| `Esc` | закрити діалог або шухляду |
| `?` | довідка по клавішах |

Обробники ігнорують натискання всередині полів введення (крім `Esc`).

## Доступ

Якщо на сервері задано `JULES_API_TOKEN`, введіть токен у «Налаштування →
Доступ»: він зберігається в `localStorage` цього браузера й додається як
`Authorization: Bearer …` (а для SSE та посилань на файли — як `?token=`).
Там само вказується ім'я, яке йде в заголовку `X-Jules-User` — сервер пише його
в `author` / `updatedBy`.
